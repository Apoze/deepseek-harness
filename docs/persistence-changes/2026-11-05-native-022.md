## Compatibility

Existing native V4 records remain readable. Recovery context retains optional settlement, skill-catalog and user-principal metadata; retry is an additional source kind on the existing user-message representation. Compaction request records are diagnostic snapshots, not a replay queue. New request-purpose and message variants are interpreted by their upstream owners; native recovery does not derive permissions or execute messages from these records. Older applications must not share the upgraded home because upstream child catalogs and schedules have separate format migrations. Rollback restores the complete pre-update home with its matching runtime, rather than downgrading only the binary.
